# MmECS 首轮性能优化与验收

日期 2026-09-26

后续补测 已通过 Profiler 原始 GC.Alloc 元数据解决当前 Editor 的分配测量缺口 见 [10-GC分配专项报告](10-GC分配专项报告.md) 下文保留首次优化时的测量事实 原线程计数接口仍不可用 原耗时结果不与开启 Profiler 的测量混用

## 问题

- 移动循环每实体调用两次 `World.Get<T>` 每次都查组件类型字典 1 万实体每步产生 2 万次重复类型查找
- 原结构基准将每个实体的 Add 和 Remove 相邻入队 标签池最多只有一个成员 未实际测到中间行填洞
- 编辑器线程分配计数器校准失败 缺少目标设备预算 因而不能得出零 GC 或产品性能达标结论

首次移动拆分实测为查询 0.2883 ms 旧路径更新 2.8365 ms 独立池访问 0.3427 ms 完整移动 3.1609 ms 说明优先减少访问开销合理 各项独立计时 不将其差值当作精确的类型字典耗时

## 修复了什么

仅新增 `ComponentLookup<T>` 值类型与 `World.GetLookup<T>` 工厂 移动系统在循环前获取位置及速度的 Lookup 循环内直接访问已绑定的池 从每实体两次类型查找变为每系统每 Tick 两次

新增运行时代码约 50 行 包含职责注释 世界及池字段构造 Get 与工厂 移动系统只改变组件访问位置 没有新增调度器或系统业务状态

保留以下契约

- Lookup.Get 验证本世界的存活代际 组件池继续验证组件存在
- 世界池不对外暴露 不增加即时结构修改入口 FIFO 提交时间保持一致
- 查询仍按最小池筛选 数量相同时按类型注册顺序选择 不缓存匹配实体
- Lookup 缓存池对象 不缓存数组或 ref 池扩容和同世界快照恢复后可以继续用
- 组件 ref 只用于当前访问 不可跨结构提交或恢复保留 Lookup 从 GetLookup 创建 不使用 default
- Entity 仍是可信模拟内部身份 不能拿别的世界 Entity 或旧时间线 Entity 当宿主句柄使用 宿主继续采用 EntityHandle 与状态投影
- MovementSystem 每次 Tick 获取 Lookup 支持同一系统实例被调用时传入不同世界

结构基准改为先入队全部 Add 再入队全部 Remove 让池真正有多行并触发末行填洞 标签清空断言位于计时外 修改后的结构成绩不与旧报告的逐实体配对成绩直接比较

## 如何测试修复是否完成

### 测量条件

Unity 2022.3.62f3 Windows Editor Mono Intel i5-13500H 内存 32471 MB

1 万实体均含 Position 与 Velocity 每项独立世界 位置为编号模 32 速度为编号模 7 加 1 速度逆序插入以避免误将两个池的行号直接配对 步长 0.125 秒 预热 30 次 正式采样 300 次

初始化 日志 和最终核验不计时 全部实体位置使用可精确表示的二进制分数核验 并校验 Tick 总数 旧实现保留在 Editor 基准中 新旧路径在同进程依次运行 组件池基线不承担世界代际检查 不能当作同语义替代实现

### 优化后同轮对照

| 工作负载 | 旧路径均值 ms | 新路径均值 ms | 均值减少 | 旧路径 P95 ms | 新路径 P95 ms |
|---|---:|---:|---:|---:|---:|
| 完整移动 | 3.3370 | 1.4277 | 57.2% | 3.9336 | 1.9813 |
| 完整 Tick | 3.3965 | 1.4232 | 58.1% | 3.9525 | 1.8968 |

完整 Tick 为单个移动系统加输入处理和空结构提交 不含战斗或 Unity 表现 两项新均值的微小倒挂属于独立测量波动 不意味着 Tick 开销为负 完整 Tick 吞吐约为旧路径的 2.39 倍

优化前独立运行的当前移动均值为 3.1609 ms 当前 Tick 为 3.1081 ms 优化后轮次的旧实现略慢 因此主要采用同轮对照描述收益 不混合两个轮次计算加速比

原始数据见 [优化前](性能数据/移动-before.md) 与 [优化后](性能数据/移动-after.md)

### 后验审查

本轮改动未发现 P0 或 P1 功能及层级问题 参数留在 Editor 基准 通用 Core 不引用游戏或 Unity 类型 新入口无静态世界缓存 没有改生成代码 程序集依赖或序列化资源

P2 测量限制仍存在 `GC.GetAllocatedBytesForCurrentThread` 未通过明确数组分配校准 所有分配列标记不可用 不宣称零 GC 快照全量复制及逐条结构命令分配仍保留 原有诊断 Trace 默认关闭 未得到实际游戏设备或高密度战斗预算前不据此新增复杂存储及并行架构

功能验收通过 性能交付条件通过 当前结论只覆盖编辑器此工作负载 目标平台 IL2CPP 的耗时及分配量仍未验证 不宣称全局最优

## Review 顺序

1. `Assets/MmECS/Runtime/Core/W/ComponentLookup.cs` 新入口的职责及安全边界
2. `Assets/MmECS/Runtime/Core/W/World/World.Components.cs` 绑定池的工厂
3. `Assets/MmECS/Samples/Movement/Runtime/System/MovementSystem.cs` 循环前绑定与循环内访问
4. `Assets/MmECS/Editor/ComponentLookupAcceptance.cs` 生命周期和移动语义回归
5. `Assets/MmECS/Editor/MovementBenchmark.cs` 保留原实现的同工作量对照

本轮优先减少热点重复查找并保留容易审查的普通循环 未将测试代码量计入运行时复杂度 对后续优化应继续要求同工作量证据
