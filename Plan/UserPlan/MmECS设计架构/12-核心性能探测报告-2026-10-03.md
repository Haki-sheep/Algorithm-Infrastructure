# MmECS 核心性能探测

## 结论

本轮不改 Core 先测当前实现 共 3 轮 15 种工作负载 4020 次正式计时 另有 95 个 Profiler 分配区间与 4 项保留内存探测 测量前后核心行为回归均为 14/14

- 一万实体完整移动 Tick 三轮均值中位数为 0.3744 ms 五万为 1.8369 ms 本轮预热后的移动 Tick 未检测到托管分配
- 完整快照是主要预算项 五万实体捕获均值中位数为 12.7387 ms 各轮 P95 为 17.3573～20.7877 ms 每次分配约 3.79 MiB 不能默认适合逐帧保存
- 预热后的恢复复用容量 本轮恢复区间均为 0 B 这不代表冷启动 或恢复更大快照时也零分配
- 一千条同类型事件消耗 24960 B 交替类型消耗 224000 B 类型交替破坏连续批次合并 是通信路径的重点预算项
- 两秒累计时间在一万实体单移动系统上集中补 120 Tick 耗时均值中位数为 44.8835 ms 宿主接入时应明确追帧上限及剩余时间策略

## GC 分配

开启 Editor CPU Profiler 后以唯一命名区间隔离工作负载 使用主线程 RawFrameDataView 的 GC.Alloc 字节元数据 包括对象头 不把托管堆增量当作分配量 不将本阶段耗时混入计时表

校准五次全部一致 空区间 0 B 0 对象 byte[4096] 为 4128 B 1 对象 byte[8192] 为 8224 B 1 对象 两次 byte[4096] 为 8256 B 2 对象 每个标记区间在原始帧中恰好出现一次 校准不通过或区间丢失时脚本抛错

## 验证与复现

- 所有移动实体的横轴值与真实 Tick 次数一致 稀疏实体没有获得意外组件 实体数量保持不变 结构队列为空 无残留标签
- 表现批次数量与追帧实际 Tick 数均有断言 测量前后各 14 项行为回归通过
- Profiler 原始 enabled profileEditor CPU 配置均在 finally 恢复 实测恢复后全部为 false Deep Profiling 始终关闭
- 当前 Core 无修改 新增工具位于 Assets 外 不新增程序集引用 不改场景或资源
