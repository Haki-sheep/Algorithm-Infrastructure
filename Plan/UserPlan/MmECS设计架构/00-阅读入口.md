## 当前推荐

纯 C# 核心 单线程 固定 Tick 每类型紧密 Sparse Set 查询时筛选 显式系统顺序 Tick 末按入队顺序提交结构变更

对外提交 Input 和业务 Command 对外读取只读状态及表现事件 World 内的单例按世界实例持有

当前先把同版本快照的状态边界留清楚 后续按路线实现 不把联网作为 ECS 首版的前置依赖

## 从源码提炼出的关键差异

| 问题 | LeoECS Lite | Arch | MmECS 首版 |
|---|---|---|---|
| 组件存储 | 每类型组件池 回收槽位可留空 | 同组件组合的 Archetype 内按 Chunk 存放 | 每类型紧密数组 |
| 查询 | 缓存匹配实体 成员随结构变化维护 | 缓存匹配 Archetype 再遍历 Chunk | 选择最小必需池 逐候选验证 |
| 删除搬移 | 组件池留洞 Filter 成员表末行填洞 | 实体行迁移或删除后修正地址 | 组件池末行填洞并回写索引 |
| 遍历期间变化 | Filter 锁延迟的是成员表更新 | 通过结构缓冲等机制管理 | 一律延迟到 Tick 末 |
| 结构命令顺序 | 核心 Filter 延迟队列不是完整结构缓冲 | 当前缓冲按操作类别回放 | 明确 FIFO 顺序 |
| 生命周期 | 删掉最后一个组件会自动销毁实体 | 有自己的实体与版本管理 | 空实体保留 显式销毁 |

这些差异是不同成本和接口契约的选择 没有哪一列可以不加分析地复制成通用标准

## 文档编写范围与当前实现

已下载并阅读两份仓库的核心存储 查询 实体生命周期与结构变化路径 并整理为可以独立学习的文档

文档初稿编写时尚未实现 MmECS 当前工程已有 Entity World 组件池 Query 与按注册顺序执行的 Simulation 阶段 C 以及阶段 D 的固定 Tick 结构提交 入口保护 已完成 Tick 编号和目标 Tick 移动输入小步已在 Unity 验收通过 当前实现状态以源码和实测为准

参考项目的完整测试与基准仍未在当前工程运行

Arch 当前源码启用 C# 12 且包含外部依赖 支持 netstandard2.1 并不代表任意 Unity 版本都能直接编译其源码 真正接入时应验证所选编译器 预编译程序集与目标后端
