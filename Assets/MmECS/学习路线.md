## 第一阶段：核心数据层（已完成）

### Entity.cs - 实体身份管理

**核心概念：**
- Entity = Index + Generation
- Generation 从 1 开始 0 保留为无效值
- 槽位复用时 Generation 递增防止旧句柄误用

**关键代码位置：**
- `World.Create()` 优先从 freeIndexList 复用槽位
- `World.Destroy()` 删除全部组件 更新 Generation 回收 Index
- `World.IsAlive()` 校验 Index 范围 存活状态与 Generation 匹配

**检验点：**
- 为什么 Generation 要从 1 开始
- 销毁实体时为什么要先删除全部组件
- Generation 达到 uint.MaxValue 怎么办

### EntityHandle.cs - 外部句柄与时间线隔离

**核心概念：**
- EntityHandle = WorldId + StateEpoch + Entity
- StateEpoch 每次成功恢复快照时递增
- 防止跨时间线误用同一 Index Generation 的实体

**关键代码位置：**
- `World.StateEpoch` 初始为 0 恢复时递增
- `EntityHandle.TryResolve()` 校验 WorldId 和 StateEpoch
- `World.RestoreState()` 中 `StateEpoch = nextEpoch`

**检验点：**
- StateEpoch 解决什么问题 为什么 Generation 不够
- 什么场景下外部句柄会失效
- 恢复快照后宿主如何重新绑定句柄

### ComponentStorage.cs - Sparse Set 组件存储

**核心概念：**
- SparseList 实体编号到行号的映射 值为行号加一 0 表示不存在
- DenseEntityList 和 DenseValueList 保持紧密连续
- 删除时末行填洞保持有效区间连续

**关键代码位置：**
- `Add()` 扩容策略与索引建立
- `Remove()` 末行填洞与稀疏索引回写
- `Clone()` 和 `Restore()` 快照复制逻辑

**检验点：**
- 为什么 SparseList 存储的是行号加一
- 删除时为什么要回写被移动实体的稀疏索引
- 稀疏表扩容的触发条件与代价

## 第二阶段：查询与遍历 ⭐⭐⭐ 最重要

### World.Query.cs - 查询创建

**核心概念：**
- CreateQuery 接受 All 必需类型和 None 排除类型
- 按注册顺序去重并绑定组件池
- 创建后可反复执行 查询条件固定

**关键代码位置：**
- `CreateQuery()` 类型数组转组件池数组
- `ResolveQueryStorage()` 去重排序与池绑定
- `CreateCachedQuery()` 创建带缓存的热查询

**检验点：**
- 为什么要按注册顺序排序组件类型
- 查询条件中 All 和 None 的区别
- 什么时候用 CachedQuery 什么时候用普通 Query

### EntityQuery.cs - 查询执行

**核心概念：**
- 选择 Count 最小的必需池作为候选池
- 位掩码快速初筛减少逐个检查
- Matches 精确验证候选实体的全部条件

**关键代码位置：**
- `Execute()` 候选池选择逻辑
- `BuildTypeMask()` 构建位掩码 超过 64 种类型时禁用
- `Matches()` 位掩码初筛后精确检查

**检验点：**
- 为什么选最小池而不是最大池
- 位掩码如何加速 有什么限制
- Count 相同时如何打破平局

### CachedEntityQuery.cs - 热查询结果缓存

**核心概念：**
- 缓存匹配实体列表避免重复扫描
- 结构提交后标记 isDirty
- 适用于每 Tick 都执行的高频查询

**关键代码位置：**
- `GetEntities()` 检查 isDirty 并按需重建
- `MarkDirty()` 由 World.InvalidateCachedQueries 调用
- `Rebuild()` 重新扫描填充缓存列表

**检验点：**
- 热查询和普通查询的性能权衡
- 什么情况下缓存会失效
- 缓存列表的内存开销如何估算

### World.ForEach.cs - 遍历模式

**核心概念：**
- ForEach 封装查询加遍历的常见模式
- IComponentAction 接口避免装箱
- 直接访问组件池的紧密行提高缓存命中

**关键代码位置：**
- `ForEach<T1, T2, TAction>()` 双组件遍历
- 候选池选择与 EntityQuery 逻辑一致
- `action.Execute(ref comp1, ref comp2)` 直接传递组件引用

**检验点：**
- ForEach 和手动 Query 再遍历的区别
- 为什么用 IComponentAction 而不是 Lambda
- 组件引用的生命周期限制

## 第三阶段：结构变更

### StructuralBuffer.Command.cs - 延迟命令队列

**核心概念：**
- 运行期结构变更必须入队 Tick 末统一提交
- FIFO 顺序保证命令执行顺序确定性
- Add Remove Destroy 各有独立命令类型

**关键代码位置：**
- `Add()` `Remove()` `Destroy()` 入队接口
- `Commit()` 按入队顺序逐个执行命令
- `IsEmpty` 和 `PendingCount` 状态查询

**检验点：**
- 为什么不能遍历中即时 Add Remove
- FIFO 顺序的重要性
- 提交失败的处理策略

### StructuralBuffer.Spawn.cs - 延迟创建实现

**核心概念：**
- Spawn 携带初始组件数据排队创建
- 分配 SpawnRequestId 作为请求标识
- 提交后生成 SpawnResult 供消费

**关键代码位置：**
- `Spawn<T1, T2>()` 接受两种初始组件
- SpawnCommand 存储请求编号与组件数据
- 提交时创建实体并生成结果

**检验点：**
- SpawnRequestId 和 Entity 的区别
- 为什么创建也要延迟
- 当前最多支持几种初始组件

### World.Spawn.cs - 创建结果管理

**核心概念：**
- SpawnResult 保存请求编号与正式 Entity
- TryConsumeSpawnResult 取走结果并删除关联
- 结果可重复读取 消费不销毁实体

**关键代码位置：**
- `spawnResultDict` 保存未消费结果
- `TryConsumeSpawnResult()` 句柄重载校验世界与批次
- 创建结果属于快照状态

**检验点：**
- 结果取走后实体是否被销毁
- 未消费结果如何随快照恢复
- 请求编号是否跨世界有效

## 第四阶段：系统调度

### Simulation.Lifecycle.cs - 系统生命周期

**核心概念：**
- ISimulationLifecycle 提供可选的 Init Dispose
- Init 按注册顺序执行 Dispose 逆序执行
- 初始化失败清理已进入 Init 的系统

**关键代码位置：**
- `Init()` 遍历系统列表调用生命周期
- 初始化后固定系统列表
- 失败清理逻辑与异常聚合

**检验点：**
- Init 和 Dispose 的顺序为什么不同
- 初始化失败后哪些系统会被清理
- 恢复快照是否重复调用 Init

### Simulation.Tick.cs - 单步执行流程

**核心概念：**
- Tick 流程 BeginSimulation → 系统执行 → CommitStructural → CompleteTick
- BeginSimulation 标记 Tick 开始并封闭信号注册
- CompleteTick 发布事件并推进 Tick 编号

**关键代码位置：**
- `Tick()` 完整单步流程
- `World.BeginSimulation()` 开始阶段状态设置
- `World.CommitStructural()` 提交结构变更并失效缓存

**检验点：**
- 为什么要 BeginSimulation
- 结构提交在什么时机
- Tick 失败后状态如何保证

### Simulation.Runner.cs - 固定步长与追帧

**核心概念：**
- Advance 累计引擎时间执行零到多个 Tick
- 固定步长保证逻辑确定性
- 单次 Advance 可能执行多个 Tick

**关键代码位置：**
- `Advance()` 时间累计与 Tick 循环
- 固定步长验证
- 追帧上限由调用方控制

**检验点：**
- 为什么需要固定步长
- 单次 Advance 最多执行多少 Tick
- 引擎帧时间和逻辑 Tick 的关系

## 第五阶段：通信机制（可选）

### SignalBus.cs - 同步信号

**核心概念：**
- Emit 时立即回调已绑定系统
- 系统实现 ISignalSystem 绑定 ISignalHandler 处理
- 初始化后封闭注册

**关键代码位置：**
- `Emit()` 遍历订阅列表立即回调
- `Seal()` 封闭注册阶段
- 信号类型与处理器绑定

**检验点：**
- Signal 和 Event 的区别
- 为什么要封闭注册
- Signal 的执行顺序

### EventBus.cs - 表现事件

**核心概念：**
- Emit 累积事件按 Tick 分批
- 宿主通过 TryPeek Acknowledge Dispatch 消费
- 未确认批次不释放 恢复时清空

**关键代码位置：**
- `Emit()` 写入当前 Tick 批次
- `Publish()` 封闭当前批次
- `TryPeek()` `Acknowledge()` 消费流程

**检验点：**
- 为什么要按 Tick 分批
- 未确认批次的生命周期
- 恢复快照后事件如何处理

## 第六阶段：快照系统（可选但重要）

### World.Snapshot.cs - 状态捕获与恢复

**核心概念：**
- 快照保存实体分配器 组件池 单例 Tick 随机源 创建结果
- 只能在完整 Tick 边界且结构队列为空时操作
- 恢复时 StateEpoch 递增

**关键代码位置：**
- `CaptureState()` 完整状态复制
- `RestoreState()` 状态恢复与 StateEpoch 递增
- `EnsureSnapshotBoundary()` 边界检查

**检验点：**
- 什么被保存什么不被保存
- 为什么只能在 Tick 边界操作
- StateEpoch 溢出如何处理

### World.Handles.cs - 外部句柄管理

**核心概念：**
- GetEntityHandle 绑定当前世界与批次
- TryResolve 校验 WorldId StateEpoch 和实体存活
- 恢复后通过 ReadEntityHandles 重新绑定

**关键代码位置：**
- `GetEntityHandle()` 创建外部句柄
- `TryResolve()` 句柄解析与校验
- `ReadEntityHandles()` 恢复后批量重绑

**检验点：**
- 外部句柄和内部 Entity 的区别
- 什么情况下句柄会失效
- 重新绑定的正确时机
