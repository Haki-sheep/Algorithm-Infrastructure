**1．TTF / OTF：源字体文件**

它提供：

- 字符到字形的映射；
- 字形轮廓；
- 字宽、基线、间距等排版信息。

它的大小主要取决于字形数量、轮廓复杂度和排版数据等。

**裁剪源字体可以减少包体，但被裁掉的字形无法再从这份字体动态生成。** 例如把源字体裁成常用 7200 字，就只能提供这份字符集覆盖的字形，并不代表能覆盖所有中文、日文或其他语言。

**2．TMP Font Asset：TMP 使用的字体资源**

它保存字符表、字形表、排版信息，并关联图集纹理、材质，以及可选的 fallback 字体。

**字符、字形、纹理和图集分别是什么？**

以“傅”为例：

- **字符：**文字的编码，确定要显示哪个字。
- **字形：**这个字在某种字体中的具体外形，例如宋体和黑体的“傅”长得不同。
- **纹理（Texture）：**供 GPU 使用的像素数据，可以理解成一张图片；字形也能生成到这张图片里。
- **字体图集（Atlas）：**把许多字形集中放进一张或多张大纹理，并记录每个字形的位置。

字体图集与按钮、道具图标的图片图集思路相同，只是其中装的是字形。它通常直接把字形生成到图集中，不需要先为每个字保存一张独立 PNG，也不是只管理一组分散的图片文件。

```text
一张字体图集纹理（示意，实际字形不一定整齐排列）
┌───────────────────────┐
│  你   好   傅   游   戏 │
│  开   始   确   认   取 │
│  消   0    1    A    B  │
└───────────────────────┘
```

**烘焙就是把源字体中的字形轮廓转换成可供渲染的像素数据，填入图集。**

显示“你好”时，TMP 查出两个字形在图集中的区域，为它们生成用于绘制的小矩形，按字宽和间距排好，再由 GPU 通过纹理坐标（UV）读取对应区域进行绘制。通常不会为整句“你好”再生成一张独立图片；多个文本可以复用同一个字形。

```text
字符 → 查找 TTF 字形轮廓 → 烘焙到图集纹理
                              ↓
                  TMP 查找字形并排版 → GPU 绘制
```

**常用的 TMP SDF 图集是一种特殊的字形纹理。** 像素编码的是到字形边界的距离信息，Shader 据此重建文字边缘，并实现描边等效果。因此它比直接放大普通文字图片更适合缩放，但仍有清晰度限制，也仍然占用纹理内存。

TMP 字体分为静态和动态，区别是字形何时生成：


| 类型  | 字形生成时机        | 是否需要运行时使用源字体 |
| --- | ------------- | ------------ |
| 静态  | 编辑器中提前烘焙      | 显示已烘焙字符不需要   |
| 动态  | 运行时遇到新字符时按需生成 | 需要对应的源字体     |


**3．静态烘焙：提前生成需要的字形**

静态字库在编辑器中提前把所需字形放入图集，游戏中直接使用。它只能使用已经烘焙的字形，不会自行补字。

可以通过以下方式减少资源大小：

- 减少烘焙字符数量；
- 更紧凑地排列字形；
- 合理降低采样字号（烘焙时的字形像素尺度，不是直接降低 UI 显示字号）；
- 合理降低字形周围的 Padding（留给距离场及描边等效果的空间，不是屏幕上文字的排版间距）；
- 缩小图集尺寸或减少图集数量；
- 压缩发布资源包。

其中需要区分：

- **减少字符、紧凑排列后，通常还要缩小图集或减少张数，才能明显降低纹理内存。**
- **资源包压缩主要减少存储、下载量，不等于减少加载后的纹理内存。**
- 采样字号和 Padding 过低，会影响清晰度及描边、阴影效果。
- 如果所有文字都能由静态字库覆盖，且没有其他依赖，可以不把源 TTF 带入发布包。

**4．动态烘焙：遇到新字符时生成，并缓存复用**

动态字体显示一个字符时：

```
图集中已经有这个字形 → 直接使用
图集中还没有这个字形 → 从源字体生成 → 写入图集 → 后续复用
```

这里的“写入图集”是把新字形填入现有纹理的空位；图集装满后，可按设置新增一张图集。它并不是为每次显示、每个文字对象都创建一张新图片。

它正常工作的条件是：

- TMP Font Asset 设置为 `Dynamic`；
- 关联的源字体可用，并包含目标字形；
- 图集可写入，且有足够空间；
- 当前图集装满时，若要继续扩展，需要允许多图集。

**不需要每帧重新烘焙，同一字形生成后通常会缓存复用。** 正常显示时，TMP 会自动触发补字，一般不需要自己写缺字生成代码；也可以通过代码提前预热。

动态方案的成本包括：

- 首次生成字形的计算；
- 图集更新与纹理上传；
- 源字体及运行时数据；
- 随字符数量增长的图集内存。

一次出现大量新字可能造成卡顿。它也没有一个简单开关，能把全部烘焙工作自动交给 GPU 后台完成。

**5．Fallback：找不到字符时继续查找的备用字体**

TMP 的 fallback 列表中放的是 **其他 TMP Font Asset，不是直接放 TTF**。

```
主字体找不到字符
    ↓
查找 fallback 字体
    ├─ 静态字体：使用其中已有的字形
    └─ 动态字体：已有则复用，没有则尝试从源字体生成
```

因此：

- fallback 可以是静态，也可以是动态；
- 动态字体可以作为主字体，不必须放在 fallback；
- 只有动态字体的源 TTF 包含目标字形，才有可能动态补出这个字；
- 所有可用字体都没有目标字形时，仍然会缺字。

**6．字体大小要分成三个指标**


| 指标       | 代表什么                        |
| -------- | --------------------------- |
| 工程文件大小   | 硬盘中的 TTF、TMP `.asset` 等文件大小 |
| 发布包／下载大小 | 资源经过构建、压缩后的大小               |
| 运行时内存    | 实际加载的字体、图集及运行时数据占用          |


**三者不能直接画等号。**

五份原始文件共 50MB，压缩成 20MB，完整还原这些文件内容仍是 50MB；但游戏是否全部同时加载，以及最终占用多少内存，是另一个问题。

- 按需加载主要控制同时占用的内存。
- 按需下载主要控制首包和用户下载量。
- 裁剪字符、减少字体数量、缩小图集，才是在减少资源数据本身。

图集尺寸之所以影响内存，是因为纹理要保存整张图片的像素。以未压缩、无 mipmap 的 Alpha8 图集为例，每个像素占 1 字节：


| 单张图集尺寸      | 单份像素数据量 |
| ----------- | ------- |
| 1024 × 1024 | 约 1MiB  |
| 2048 × 2048 | 约 4MiB  |
| 4096 × 4096 | 约 16MiB |


**宽高各翻倍，像素数据量变成四倍。** 即使图集里还有空白，已分配纹理的像素数据仍按整张尺寸计算。上述数字不包含可读纹理的 CPU 副本、源字体、字符表等额外开销，也不代表所有纹理格式都按这个比例占用内存。

**7．TTF 大小与 TMP 图集大小没有固定比例**

TTF 大，生成的 TMP 字库不一定大，关键看实际烘焙了什么：

- 10MB 的 TTF，只烘焙十个数字，可以生成很小的图集。
- 同一份 TTF，烘焙 7200 个汉字，可能需要很大的图集或多张图集。
- 源 TTF 裁剪变小后，如果烘焙字符和图集配置没变，TMP 图集未必变小。

**源字体裁剪和图集优化，是两件相关但独立的事。**

**8．动态字体可能省初始内存，但不保证省总内存**

静态准备了 7200 个字，玩家实际只看到 500 个时，动态方案只生成实际需要的字形，可能节省图集空间。

但它还要保留源字体，图集按整张分配，缓存也会逐渐增长。如果最终使用了同样多的字形，动态方案未必比静态更省内存。

实际选择可以是：


| 内容            | 常见选择                 |
| ------------- | -------------------- |
| 固定 UI、剧情、配置文案 | 收集实际字符，静态烘焙          |
| 昵称、聊天、不可预知文字  | 动态字体或动态 fallback     |
| 优先减少预生成资源     | 裁剪源字体＋动态生成，并评估首次生成耗时 |


**静态提前支付字形生成成本；动态按需支付并缓存。最终要同时看下载体积、首次显示耗时和峰值内存，不能只看某个字体文件有多大。**
